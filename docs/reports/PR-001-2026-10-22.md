## 1. Summary

Stage 0 now produces programs for two targets, Linux x86-64 and Windows x64, and passes a 64-test conformance battery on
both. Two correctness bugs found by running the compiler on 21 October are fixed and covered by regression tests. Every
statement about status, on the website, in the README and in the progress log, is now generated from one file and
checked by a test. A direction (security, then AI, then quantum) is written down as Canon Amendment A-1, with tests for
each step. Stage 1 is unchanged and still scaffolding; self-hosting has not been attempted.

## 4. Speed (unchanged this period)

One workload, 1,048,576 comparisons, `hyperfine` 100 runs after 3 warm-ups, pinned to one core. Dhar is about 15.5 times
slower than optimised C by the median and 5.3 times by the mean, and 11.7 to 20.3 times faster than Node.js, PHP, Java and
Python by the median. The README quotes both columns because at a millisecond or two the mean flatters Dhar. The table is
generated from `benchmarks/results/*.json`. No code-generation change this period affects the benchmark workload, and it
was not re-run.

## 5. Limits that matter

* The Windows output has not run on a real Windows machine. It is **Partly**, not **Works**.
* `dharc` itself runs only on Linux. Windows users would run it under WSL.
* ARM64, RISC-V and WebAssembly do not exist. They are planned as Stage 1 back ends ([MULTI-ISA-PLAN.md](../MULTI-ISA-PLAN.md)).
* Stage 1 is eight files of scaffolding. Nothing in the direction (security, AI, quantum) is built.
* The browser playground does not exist.
* The Canon documents themselves were not available for editing; the amendments are in `docs/canon/` and still need to be
  applied to them.
