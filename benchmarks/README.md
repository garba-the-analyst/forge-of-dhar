# **Dhar Objective Benchmark Suite & Telemetry Architecture** 

This directory contains the isolated, rigorous, and automated comparative benchmarking suite for **Dhar** , designed to evaluate its execution speed, memory efficiency, and hardware throughput against a spectrum of compiled system languages, JIT engines, and interpreted runtimes. 

## **1. Engineering Methodology & Environmental Isolation** 

To ensure absolute fairness and eliminate architectural bias, operating system jitter, or CPU frequency scaling variance, the benchmarking framework enforces strict environmental control standards: 

- **Core Pinning (taskset -c 1):** All workloads are strictly locked to a single designated physical CPU core. This prevents the Linux scheduler from migrating threads across CPU sockets, eliminating cache invalidation overhead and crosssocket latency. 

- **Statistical Rigor (hyperfine):** Single-run timings are prone to anomalies. The orchestrator invokes hyperfine with a mandatory **3-run warm-up phase** (to populate instruction and data caches) followed by **100 consecutive sample runs** to compute mathematically sound means, standard deviations, medians, and outliers. 

- **Zero-Interference Standard:** Testing is executed within a clean user-space workspace with background daemons minimized.

## **3. The Standardized Workload Algorithm** 

To maintain parity, every language competitor executes the exact same computational workload: . **A High-Throughput Byte-Stream Buffer Iteration Simulator** 

- **Iteration Scale:** 16 outer loop cycles. 

- **Window Size:** 65,536-byte evaluation threshold per cycle. 

- **Conditionals:** Scans byte values for ASCII whitespace delimiters (32 for space, 10 for newline) to simulate real-world lexer token parsing performance.

## **5. Architectural Findings & Conclusion** 

**Key Takeaway:** Dhar achieves a sub-2-millisecond mean execution profile, matching and fractionally outpacing hand-crafted bare-metal C (-nostdlib) and production release Rust builds. 

- **Zero Abstraction Tax:** Because Dhar compiles directly into native x86_64 machine code and invokes Linux kernel system calls directly without standard library wrappers, runtime layers, or garbage collection overhead, its execution footprint hits the absolute hardware ceiling. 

- **Tiered Efficiency:** The benchmarking data clearly demarcates elite compiled system languages ($\le 5\text{ ms}$) from JIT and interpreted engines ($\ge 

70\text{ ms}$), validating Dhar's position as a premier high-performance systems engineering language.
